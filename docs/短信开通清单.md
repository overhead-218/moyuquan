## 六、双通道架构说明

```
App 登录页（零改动）
   ↓ POST /sms {action:"send"|"verify"}
云函数 sms（按 SMS_PROVIDER 环境变量分流）
   ├─ aliyun  → SendSmsVerifyCode  / CheckSmsVerifyCode
   └─ tencent → 腾讯云 SendSms（原有逻辑，一行未改）
```

**两条通道的实质差异 —— 验证码存哪**

| | 阿里云通道 | 腾讯云通道 |
|---|---|---|
| 码由谁生成 | 阿里云生成并保管 | 我们自己生成 |
| 库里存什么 | 空串（只当发送记录，用于限流） | HMAC-SHA256(pepper, phone\|code) |
| 怎么校验 | 调 `CheckSmsVerifyCode`，看 `Model.VerifyResult == 'PASS'` | 查库比对哈希 |
| 防重放 | `DuplicatePolicy=1`（覆盖，旧码自动失效） | `used` 标记 |

> ⚠️ **阿里云通道的 `TemplateParam` 必须传 `{"code":"##code##","min":"10"}` 占位符**，
> 让阿里云生成码。传明文的话阿里云**无法校验**（官方文档明确说明），
> 那样就等于放弃了免资质方案的核心好处。
> 代码里有断言测试守着这一点（`tool/test_aliyun_sign.js`）。

**未显式配置 `SMS_PROVIDER` 时**：按「哪边配齐了用哪边」自动判断（阿里云优先），
即使忘了改环境变量也不会整个挂掉。

## 七、安全设计（已实现，别绕过）

- **验证码不落明文**：
  - 腾讯云通道 —— 库里只存 `HMAC-SHA256(CODE_PEPPER, phone|code)`
  - 阿里云通道 —— 我们连明文都拿不到，库里 `code` 字段是空串
  - 两种情况下攻击者用 App 里公开的 Publishable Key SELECT 出记录都算不出 6 位码
- **AccessKey / SecretKey 永不下发客户端**：App 直连云 API 会被反编译提取密钥 → 盗刷短信费
- **IP 频控**：同 IP 每小时 20 条、单日 60 条（进程内计数，多实例时不精确，
  是兜底而非唯一防线；真正的硬防线是阿里云套餐包额度上限）
- **单号频控**：60 秒重发间隔、单日 5 条上限
- **错误次数锁定**：腾讯云通道错满 5 次作废；阿里云通道由 `DuplicatePolicy` + 有效期内唯一保证
- **mock 模式的测试码只在 debug 包显示**，release 包不外显（合规要求）

## 八、常见错误码对照

| 错误码 | 含义 | 怎么办 |
|---|---|---|
| `SMS_NOT_CONFIGURED` | 环境变量没填/没部署 | 跑收尾脚本；改完配置**必须重新 deploy** |
| `FUNCTION_NOT_OPENED` | 阿里云「短信认证」功能没开 | 控制台 → 功能开启 → 打开开关 |
| `MOBILE_NUMBER_ILLEGAL` | 手机号格式错 | 11 位、1 开头 |
| `BUSINESS_LIMIT_CONTROL` | 号码天级流控 | 换号或明天再试 |
| `TOO_FREQUENT` | 60 秒内重复发 | 等 60 秒 |
| `DAILY_LIMIT` | 单号当日 5 条用完 | 明天再试（换号测试更快） |
| `IP_RATE_LIMITED` | 触发 IP 频控 | 等一会儿 |
| `CODE_EXPIRED` | 超过 10 分钟 | 重新获取 |
| `CODE_MISMATCH` / `WRONG_CODE` | 码不对 | 注意别连错 |
| `TOO_MANY_FAILS` | 错满 5 次作废 | 重新获取 |
| `SMS_API_ERROR` | 服务商侧报错 | 看返回里的 `aliyunCode` 具体定位 |

## 九、遗留风险

- **赠送签名不可自定义**：用户收到的短信署名是平台名，不是「摸鱼圈」。
  介意的话只能走个体户 + 腾讯云。
- **阿里云通道拿不到明文码**：如果将来要做「验证码回填率统计」之类的分析，
  阿里云侧要单独开「状态报告接收」（HTTP 推送）才能拿到回执。
- **IP 频控是进程内计数**：云函数多实例时每个实例各有一份，限流会偏松。
- **anon 可上传对象存储**（`spot-photos` 桶）：任何人能往自己 uid 目录塞文件消耗存储，
  收紧要等真实身份认证接上。
