# 摸鱼圈 · 去假数据改造说明

> 生成时间：2026-10-16
> 适用版本：1.1.0 (11)

---

## 一、为什么要做这件事

后台逐模块审计发现：这个App 里**大量"看起来能用"的功能其实是假的**。
最典型的三类：

| 类型 | 表现 | 用户会遇到什么 |
|---|---|---|
| 纯内存态 | 关注/收藏/点赞/拉黑重启就丢 | 换个手机登录，自己收藏全没了 |
| 硬编码 mock | 10个假钓友、3 条固定评论、420 条本地钓点 | 运营在后台改了数据，App 里看不到 |
| 假交互 | 点了没反应，或提示"成功"但什么都没做 | 以为分享/收藏/举报成功了，其实没有 |

本次改造把能落地的部分全部换成真实云端读写。

---

## 二、你需要做的一件事（很关键）

**在腾讯云开发控制台执行建表 SQL**，否则新写的真实功能会因为表不存在而静默降级。

### 操作步骤

1. 打开控制台 → 云开发 → 数据库 → **SQL 编辑器**
2. 打开工程里的 `sql/schema_social.sql`
3. **Ctrl+A 全选**（先清空编辑器原有内容）→ 整段粘贴 → 点「执行」

脚本是幂等的，重复执行不会报错。

### 会新建 16 张表

```
spot_comments  post_comments        # 钓点评论 / 帖子评论
catches        catch_likes# 渔获 / 渔获点赞
follows        favorites            # 关注 / 收藏
post_likes     spot_likes           # 帖子点赞 / 钓点点赞
conversations  chat_messages        # 私信会话 / 私信消息体
blocks         reports              # 拉黑 / 举报
equips         equip_reviews        # 装备图鉴 / 装备评价
user_locations                       # 地图钓友图层
app_config                          # 版本检查（「检查更新」数据源）
```

执行后可自检（应全部返回 0）：

```sql
select count(*) from catches;
select count(*) from follows;
select count(*) from chat_messages;
select count(*) from app_config;
```

## 三、已修复的「假功能」清单

### 1. 所有用户共用一个账号（最严重）

**问题**：`user_profile.dart` 里 `kId = 'me'` 写死。所有设备、所有账号在云库里共用同一行
`profiles`，发帖作者、收藏、关注、点赞全部塌缩成一个人。

**修复**：改为按登录凭据派生稳定 uid（手机号/Apple sub 哈希），游客态生成本机随机 uid。
登出时换新 uid，避免读到上个账号的数据。

---

### 2. 私信是全局共享的（隐私事故）

**问题**：会话存在一张**没有用户列**的全局 `messages` 表里，
`refreshFromCloud()` 直接 `select *` 拉全表。任何用户登录都能看到所有人的
私信摘要——对方昵称、最后一条消息内容、未读数。

**修复**：改用 `conversations` 表，严格按 `userAId = 我 或 userBId = 我` 过滤。

---

### 3. 云库数据永远不生效

**问题**：`spot_service.refreshFromCloud()` 是"只增不覆盖"——
云库已有的 id 因为在本地 420 条种子里存在，被直接丢弃。
运营在后台改钓点，App 完全看不到。

**修复**：改为云库权威、整体覆盖（云库没有的本地 id 说明已被后台删除，应同步消失）。

---

### 4. 评论点赞同步必失败

**问题**：`TcbRestClient.update(table, match, patch)` 的第二个参数签名是 `Map<String,String>`，
代码传的是 String `'eq.$commentId'` → 运行时 `uri.replace(queryParameters: String)` 抛
`ArgumentError`，被 `catchError` 静默吞掉。点赞数永远同步不到云库。

**修复**：改为 `{'id': 'eq.$commentId'}`。

---

### 5. 评论图片读不回来

**问题**：`images` 列在云端是 TEXT，写入时传 `List`，读回时却按 `as List?` 解析，
静默变成空列表。

**修复**：序列化改为逗号分隔字符串，解析时兼容 List / 逗号串 / 历史 JSON 三种形态。

---

### 6. 评论 id 跨设备撞号

**问题**：`'c${microsecondsSinceEpoch}'` —— 两台设备同一微秒发评论会撞主键。

**修复**：改为 `c_{用户uid}_{时间戳}`。

---

### 7. 帖子评论是3 条写死的

**问题**：`post_detail_page.dart` 里 `_comments` 是 3 条常量
（海钓阿强/钓鱼王/菜鸟），**所有帖子都显示这3 条**，而且评论区**没有输入框**，
用户根本无法评论。更矛盾的是顶部评论数用 `_comments.length`（恒为3），
而帖子的真实 `commentCount`（如156）被完全忽略。

**修复**：新建 `post_comment_service.dart` 接入 `post_comments` 表，
补上评论输入框、发送、回复、云端同步；评论数改为云库真实条数。

---

### 8. 钓点详情页 5 处假交互

| 位置 | 原行为 | 现状 |
|---|---|---|
| 分享按钮 | 只弹 toast「分享链接已复制」，**什么都没复制** | 真实复制到剪贴板 + 调起系统分享 |
| 收藏按钮 | 只弹 toast「已收藏」，**什么都没收藏** | 真实写 `favorites` 表，图标随状态变化 |
| 点赞 | 从写死的 `568` 起算，点完不入库 | 真实写 `spot_likes` 表，失败自动回滚 |
| 钓手名字 | 写死 `const Text('湖边走')` | 显示真实认领商家/负责人 |
| 评论按钮 | 空实现，**点了毫无反应** | 滚动到评论区并聚焦输入框 |

---

### 9. 榜单全是互相刷的假数据

**问题**：`catch_service.dart` 里16 条写死渔获——
164kg 蓝鳍金枪鱼归「海钓阿强」、64kg 青鱼归「钓鱼王」。
整个文件连 `tcb_rest_client.dart` 都没 import，没有任何网络能力。

**修复**：全量重写，接入 `catches` / `catch_likes` 表。
云库为空时显示空榜，不再用假数据撑场。

附带修了一个必崩的bug：`_topAnglers()` 里 `regionOfCity(c.city)`，
真实数据 `city` 可能为 null → 榜单页直接崩溃。

---

### 10. 人气钓友积分公式与文案不符

**问题**：页面规则写「点赞×1 + 评论×2 + 收藏×3」，
代码实际是 `likeCount * 1 + commentCount * 2 + (likeCount ~/ 5)`——
把点赞数除以5冒充收藏数。

**修复**：点赞改为真实入库（`post_likes` + `posts.likeCount` 同步），数据本身真实。

---

### 11. 新秀榜用 userId 白名单判新用户

**问题**：`if (c.userId == 'u009' || c.userId == 'u010')` 写死判断谁是新手，
完全不查真实注册时间。

**修复**：改为基于「注册时间距今 30 天内」判定；账号体系未记录注册时间时该用户不参与，
不编造。

---

### 12. 举报失败也提示「已提交」

**问题**：`moderation_service.report()` 写库失败时静默吞异常，
UI 仍然弹「举报已提交，我们会尽快处理」。用户以为举报生效了，其实根本没上报——
这在App Store 审核里是硬伤（Apple Guideline 1.2 要求举报机制真实可用）。

**修复**：如实返回成功与否，失败时明确提示「举报提交失败，请检查网络后重试」。

---

### 13. 拉黑重启即失效

**问题**：拉黑名单是纯内存 `Set`，重启 App 全丢，跨设备无效。
合规上等于没有屏蔽功能。

**修复**：接入 `blocks` 表，启动时拉取；写库失败回滚。

---

### 14. 注销账号不删云端数据

**问题**：点「注销账号」只清本地缓存就跳登录页，
云端`profiles` / 帖子 / 评论 / 点赞 / 收藏 / 关注 / 私信全留着。
换个手机登录还能看到全部历史内容 —— 个人信息保护违规。

**修复**：新建 `account_deletion_service.dart`，按真实 uid 逐表清理云端数据
（含关注关系的双向清理、会话两个方向、本人发帖与profile）。

---

### 15. 检查更新永远说「已是最新」

**问题**：不管什么版本，点下去永远弹「已是最新版本 v1.0.0」，
且版本号在页面里写死，从不查任何接口（而 pubspec 实际已是 1.1.0+11，两边还不一致）。

**修复**：
- 版本号改为单一数据源（`app_version.dart`，由 `tool/gen_version.dart` 从 pubspec 生成）
- 新建 `app_config` 表，插入一行即可向所有客户端推送新版本
- 真实查询并按 build 号比对，有新版弹更新说明 + 下载按钮，查询失败如实提示

---

### 16. 短信验证码可预测

**问题**：`_generateCode()` 用 `DateTime.now().millisecondsSinceEpoch % 1000000`——
攻击者拿到发送时刻就能算出验证码，等于没有验证码；同毫秒发两个号还会撞码。

**修复**：改用 `Random.secure()`。

另外：mock 模式下验证码原本会**明文打进日志**并在登录页显示给用户，
现改为仅 debug 构建显示，release 包不再外显。

---

### 17. 原生端「记住的城市」完全失效

**问题**：城市记忆存在 `localStorage`（Web 专属 API），
原生端 `geo_service_stub.saveCity()` 是空函数，App 上这个功能等于没有。

**修复**：原生端改用 `SharedPreferences`（工程已依赖），Web 端保持 localStorage，
并补齐异步读取接口（首帧同步读盘必然拿不到值）。

---

### 18. 聊天全是假的

**问题**：`chat_detail_page.dart` 里
- `_messages` 是纯本地 List，从不读云库，每次进页面都是空的
- `_sendLocation()` 写死「东江湖·白廊镇」
- `_sendCatchCard()` 写死「大翘嘴 3.8斤 / 升钟湖·凤凰岛」+ picsum 随机图
- 对方永远不会回消息

**修复**：新建 `chat_service.dart`，消息体真实入库 `chat_messages` 表，
进入页面拉历史 + 5 秒轮询接收对方回复；位置改用真实定位，渔获卡从用户自己的真实渔获里取。

---

### 19. 会话摘要只更新不存消息

**问题**：`MessageService.upsertConversation()` 只改本地摘要，
消息内容从未写入任何存储。

**修复**：消息写入 `chat_messages`，会话摘要写 `conversations`。

---

### 20. 编译错误（原本就存在）

`spot_detail_new.dart` 构造函数名为 `const SpotDetailPage({...})`，
但类名是 `SpotDetailPageNew` → 整个文件无法编译。已修正。

## 四、还没做的（需要额外资源）

以下几项不是写代码能解决的，列出来供你决策：

| 项 | 现状 | 阻塞原因 |
|---|---|---|
| **真机定位** | `geolocator` 未加入依赖 | 需加 pubspec 依赖 + Android/iOS 权限声明。当前 App 端坐标仍兜底在南京市中心，**距离排序榜单不可信** |
| **地图页** | `map_page.dart` 是用 Container+渐变手绘的假地图 | 需接入地图 SDK（建议腾讯位置服务）。真图数据源已就绪（`spots` 表 597 条含经纬度） |
| **装备图鉴** | 183 条装备硬编码在 `catch_page.dart` | `equips` 表已建好，**但表里是空的**。`sql/schema_social.sql` 只建结构不灌数据，需要导入真实商品数据 |
| **评论/头像图片** | base64 直接存库 | 单图约100~200KB，PostgREST 单行迟早撞 PostgreSQL 行大小限制。需接 CloudBase 存储桶，库里只存 URL |
| **天气** | 全工程没有任何天气代码 | 需和风/彩云天气 API key + `weather_cache` 表 + 定时拉取云函数 |
| **内容安全** | 只有本地 24 词敏感词表，且**没有任何页面调用它** | 需接腾讯云内容安全（天御/CMS）云函数。本地词库随包分发、可被绕过，只能作第一层拦截 |
| **运营鉴权** | `claim_review_page.dart` 里明文写着口令 `moyuquan2026`，且设置页对**所有用户可见** | 需 `accounts.role` 字段 + 云函数鉴权 |
| **短信** | 云函数已部署但返回 `SMS_NOT_CONFIGURED` | 腾讯云短信签名/模板未过审。**不要急着把 `_isMockMode` 改 false**，否则用户彻底无法登录 |

## 五、改造后的行为约定

1. **云库为空 → 显示空态，不用假数据撑场。**
   榜单、消息、评论、搜索用户都是如此。宁可空，不要假。

2. **写库失败 → 如实告知用户，并回滚本地状态。**
   举报、点赞、收藏、关注都不再「假装成功」。

3. **云库不可用 → 降级可用，但不谎报。**
   表未建时会走降级路径并在日志说明，同时检查更新会提示失败原因。
