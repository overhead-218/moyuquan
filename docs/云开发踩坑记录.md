## 一、PostgREST 列名大小写：每张表规则都不同，必须先探测

PostgREST 直连 PG，**列名大小写敏感，且不同表规则不一样**：

| 表 | 规则 | 例子 |
|---|---|---|
| `profiles` / `conversations` / `chat_messages` | 建列时写的驼峰会被 PG **归一成全小写** | `loginMethod` → `loginmethod`，`userName` → `username`，`senderId` → `senderid` |
| `posts` / `equips` / `spots` | 驼峰**原样保留** | `imageUrl`、`likeCount`、`priceTiers` |

**动手前必须探测**，不要套用别的表的经验：

```bash
curl -H "Authorization: Bearer $KEY" \
  "$GW/v1/rdb/rest/spots?select=priceTiers&limit=1"
# 200 = 列名正确；400 DATABASE_42703 = 列名不存在
```

查全量列清单（最可靠）：

```bash
tcb db execute -e $ENV --sql \
  "select column_name from information_schema.columns
   where table_name='spots' order by ordinal_position;"
```

### 建列必须带双引号

```sql
-- ✅ 正确：保留驼峰，与 spots 现有列风格一致
alter table spots add column if not exists "priceTiers" jsonb default '[]'::jsonb;

-- ❌ 错误：会被归一成 pricetiers，前端读驼峰永远读不到
alter table spots add column if not exists priceTiers jsonb default '[]'::jsonb;
```

**本次实战**：`sql/part6.sql` 原来没加引号，导致 4 列看起来「执行了」但实际建成小写，
前端读 `priceTiers` 全部 42703。已改为带引号并由 `tool/run_part6.py` 执行生效。

## 二、派生字段绝不能进 `toJson()`

云库没有的列一旦写进请求体，**整条 insert/upsert 报 PGRST204 失败**，
不是「忽略这个字段」，是全条写不进去。

本次实战：`Spot.toJson()` 里带了 `imageSource`（由 `images`/`submitter`/`imagesVerified`
实时算出的派生字段），云库 `spots` 表无此列 → 商家提交/编辑钓点全部失败。
已从 `toJson()` 移除，并在 `fromJson` 里保留实时计算。

**防复发**：`tool/check_spot_json_keys.py` 静态比对 `toJson()` 键 vs 云库列清单，
有不匹配键就报错。建议改模型后跑一次。

## 三、`tcb db execute` 只接受单条 `--sql`

没有 `--file` 参数，也不支持多语句。写脚本逐条执行：

```python
# tool/run_part6.py
for sql in SQLS:
    subprocess.run(['tcb.cmd', 'db', 'execute', '-e', ENV, '--sql', sql])
```

- Windows 下必须用 `tcb.cmd`，用 `tcb` 会 `FileNotFoundError`。
- Python 里调 tcb 要 `shell=True`，否则拿不到 stdout。

## 四、静态托管部署：Git Bash 会把 cloudPath 吃掉（严重）

### 错误做法

```bash
tcb.cmd hosting deploy build/web / -e $ENV
```

MSYS 路径转换把 cloudPath 解析成了
`D:/Program Files/wb/WorkBuddy/resources/vendor/PortableGit/`，
于是 299 个文件被传到**这个垃圾前缀下**，站点根目录完全没更新。

**而且 `--verify` 会报「已完成发布后一致性校验」通过** —— 它只校验上传本身成功，
不校验传到了正确路径。这类「工具说成功、实际没生效」必须自己复核。

### 正确做法

```bash
MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*' \
tcb.cmd hosting deploy "C:\Dev\fishing_app_new\build\web" "/" -e $ENV
```

- cloudPath 是**位置参数**，不是 `--cloudPath`（CLI 3.8.1）。
- 本地路径用 Windows 反斜杠绝对路径，避免被转换。

### 部署后必须复核（不能只看工具输出）

```bash
# 1. 看远端 ETag 是否等于本地 md5
curl -sI "$SITE/main.dart.js?nc=$RANDOM" | grep -i etag
md5sum build/web/main.dart.js

# 2. 顺手看关键文件是否都能 200
for p in "" "index.html" "flutter_bootstrap.js" "assets/AssetManifest.bin"; do
  curl -s -o /dev/null -w "$p %{http_code}\n" "$SITE/$p?nc=$RANDOM"
done
```

CDN 可能有 1-2 分钟延迟，`--verify` 通过 + 线上 ETag 更新，两者都满足才算部署成功。

### 清理误传的垃圾文件

`tcb hosting delete <目录>` 对**含空格的目录**批量删无效，要按完整 key 逐个删：

```bash
python tool/clean_hosting_junk.py --dry-run   # 先看清单
python tool/clean_hosting_junk.py             # 确认后执行
```

## 五、对象存储：建桶与上传的 5 个坑

### 1. 环境里默认 0 个 bucket

`storage` schema 是内置的，但 bucket 要自己建。

### 2. `tcb db execute` 建桶语句过长会在 cmd shell 被截断

拆成单行逐条执行，或写 Python 脚本。

### 3. 上传必须用 **POST**，PUT → 403

```
POST {gw}/v1/storages/object/{bucket}/{key}   → 200
PUT  同上                                     → 403
```

### 4. `Content-Type` 必须在 bucket 的 `allowed_mime_types` 白名单内

不在白名单 → 400 `STORAGE_MIME_TYPE_NOT_ALLOWED`。

### 5. ⚠️ `storage.foldername('u_1/a.png')` 返回 `{u_1}`，长度是 **1** 不是 2

写 `array_length(storage.foldername(name), 1) = 2` 会导致上传 **100% 失败**。
正确写法是 `= 1`。

### 6. anon 角色下 `auth.uid()` 取不到可信值

Publishable Key 走 anon，策略**不能按 uid 绑定身份**，只能按路径形态约束：

```sql
CREATE POLICY spot_photos_authenticated_upload ON storage.objects
  FOR INSERT TO anon, authenticated
  WITH CHECK (
    bucket_id IN ('spot-photos', 'post-photos')
    AND array_length(storage.foldername(name), 1) = 1
    AND (storage.foldername(name))[1] ~ '^(guest_|u_)[A-Za-z0-9_]{1,64}$'
  );
```

**剩余风险**：anon 可上传意味着任何人都能往自己 uid 目录塞文件消耗存储。
收紧要等真实身份认证接上后再做。

### 7. public bucket 的稳定直链

```
{gw}/v1/storages/object/{bucket}/{key}
```

匿名 GET 直接返回字节，**无需签名、永久有效**。

> `tcb storage url` **不支持 PG 环境**，要用 `tcb storage objects sign`。

### 8. `tcb storage objects rm` 必须带 `-y`

否则卡在交互确认直到进程被 SIGTERM。

## 六、RLS：grant 给了权限 ≠ 能删

`part6.sql` 里 `grant ... delete on spots to anon` 已经给了，
但 `spots` 的 RLS 只有 3 条策略（SELECT/INSERT/UPDATE），**没有 DELETE 策略**。

结果：经 PostgREST 发 `DELETE` 返回 **204 但实际不删任何行**（静默失败）。

App 目前没有「删除钓点」功能，所以暂未暴露。将来要加，必须先补：

```sql
CREATE POLICY anon_delete_spots ON spots FOR DELETE TO anon USING (true);
```

**不擅自开放**：anon 可删意味着任何人拿到 publishable key 就能删钓点。

## 七、验证脚本本身的坑（比业务代码更容易骗人）

本次新写的几个验证脚本，一开始全是假阴性/假阳性：

| 症状 | 真因 | 修法 |
|---|---|---|
| `subprocess` 报 `FileNotFoundError: tcb` | Windows 要用 `tcb.cmd` | 改 `tcb.cmd` |
| 脚本 `removed 0` 什么都没做 | heredoc 里的脚本没生效 | 写成独立 `.py` 文件 |
| 探针报「列不存在」但其实列存在 | 只测了驼峰，列被归一成小写 | 用 `information_schema` 查全量列 |
| e2e 报 409 判成失败 | 409 是重复 id 的**预期**结果 | 复刻真实的 `Prefer: resolution=ignore-duplicates` |
| `UnicodeDecodeError` | 某文件非 UTF-8 | 改用 Grep 工具扫 |
| bash heredoc 跑 Python | 变量没展开 | 写独立脚本 |

**原则**：验证脚本的「通过」必须以网络/数据库实际返回为准，
不能以「脚本没抛异常」为准。

## 八、PostgREST 分页与语法

- 单次响应上限 **1000 行**，超过要分页 + `id.asc` + Set 去重。
- 空表 `select=*` 返回 `[]`，**取不到列名**，须插探针行。
- `or` 参数用**点号**：`or=(userAId.eq.me,userBId.eq.me)`。

## 九、对象存储：批量上架平台图库（2026-10-27 实测）

把本地真实照片批量上传到云存储并写回数据库，需要额外处理三件事：

### 1. 路径前缀必须匹配 RLS 的正则

策略要求第一段匹配 `^(guest_|u_)[A-Za-z0-9_]{1,64}$`：

| 用途 | 路径 | 角标 |
|---|---|---|
| 商家/用户自己上传 | `u_<uid>/xxx.jpg` | 商家实拍 / 钓友上传 |
| 平台批量上架 | `u_platform/<spotId>/NN.jpg` | **平台实拍** |
| 游客上传 | `guest_xxx/xxx.jpg` | 钓友上传 |

⚠️ 用 `platform/` 开头会被直接拒（不匹配 `u_` 前缀）。

### 2. 2 层路径需要放宽深度策略

原策略 `array_length(storage.foldername(name), 1) = 1` 只允许 1 层，
`u_platform/s251/01.jpg` 是 2 层 → 被拒。

改成 `BETWEEN 1 AND 2`（见 `sql/part9.sql`）。
⚠️ 再次提醒 `storage.foldername('u_1/a.png')` 返回 `{u_1}`，长度是 **1** 不是 2。

### 3. `--sql` 传参里的 `$` 会被 cmd shell 吃掉

```python
# ✗ 直接在 python -c 里写，正则里的 $ 被 shell 吞掉 → SQLSTATE 42601
# ✓ 写进 .sql 文件，让 Python 读出来再拼命令
sql = io.open('tool/_tmp.sql', encoding='utf-8').read().strip()
cmd = 'tcb.cmd db execute -e ENV --sql "' + sql + '"'
subprocess.run(cmd, shell=True, ...)
```

⚠️ Git Bash 的 `/tmp` 和 Windows Python 的 `/tmp` **不是同一个目录**，
临时文件要放项目内。

## 十、批量改代码文件的坑（踩过，代价是 28032 个 error）

### 不要用「字符扫描配对括号」定位代码块

第一版清洗脚本想找出所有 `images: [...]` 列表，用「找 `[` 配对 `]`」的字符扫描。
但同一文件里 **285 个是单行形态** `images: ['a','b'],`，只有 6 个是多行形态。
字符扫描把单行里的 `[` 当成多行起点 → 边界算错 → 切掉了后面的字段声明，
整个 Dart 文件语法崩掉（28032 个 error）。

**正确做法：按行处理**
- 单行：`^(\s*)images:\s*\[(.*)\],\s*$` → 整行替换
- 多行：`^(\s*)images:\s*\[\s*$` → 逐行找配对的 `],` 行

### 批量改代码前的三道保险

1. **先备份**（`cp xxx.dart /tmp/xxx.bak`）
2. **干跑**（`--dry-run` 只统计不写）
3. **写前自检**：括号配平 + 关键结构还在（`class SpotService` / `Spot(`）
4. **写后立刻 `flutter analyze`**（不要等到构建才发现）

### 回滚

备份在手就是一行：
```bash
cp backup.dart lib/services/spot_service.dart && flutter analyze lib/services/spot_service.dart
```
